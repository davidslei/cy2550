1.1. PBKDF2 is a key derivation function. It combines the passphrase with the salt and runs a hash many thousands of times to produce the key. A passphrase is relatively weak, so it must be converted into a cryptographic key using a key derivation function like PBKDF2.
1.2. The checksums are different because run picks a new random salt, which is stored at the start of the file. Because the key and IV are derived from the passphrase plus that salt, every encryption uses a different key and IV, so the output bytes come out different even for the same file and passphrase. Something that could go wrong with an encryption scheme where the two encrypted files were identical is an attacker could tell when the same message was encrypted twice just by comparing ciphertexts, without knowing the key.
1.3 ECB produced 3 distinct blocks, and the most common one repeats 24 times. CBC produced 37 distinct blocks, each appearing once. ECB leaked which plaintext blocks were identical and where they appear, so the A–B–A pattern of the file shows through. An attacker can see the data's structure and notice what changed between versions, and learn every matching block once they know the plaintext of one. How are the IV's generated?
2.2 SHA-256 hash does not protect your colleague because it has no key, so anyone can compute it. With HMAC the tag depends on a secret key that only you and your colleague share. Without that key, the attacker can't produce a valid tag for a modified file, so any change gets detected. With SHA-256, the attacker can read the file, modify it, replace the hash, and go undetected. While with HMAC, they can still read it but can't forge a new valid tag or modify the file otherwise our colleague would detect it.
3.3 Email verification proves that the person who requested the key can access the email account at that address, but doesn't prove if the person actually owns the identity associated on the key. You would have to meet up with the classmate in person and have them read their fingerprint from their own computer and compare it with the fingerprint of the downloaded key. If every character matches, then it really belongs to our classmate. This works because the interaction takes place over a channel the attacker can't potentially control, so they can't intercept/alter it.
4.2. Pubkey enc packet contains a randomly generated symmetric session key that was encrypted with my RSA public key. The encrypted packet contains my actual message that was encrypted with a Cipher. GPG uses this approach instead of just using RSA to encrypt the entire message because RSA is slow and can only encrypt data smaller than its key size, while AES is fast and can handle any size. This construction is called hybrid encryption.
4.3. The signer's private key is used for signing. The signer's public key is used for verifying. The recipient's public key is used for encryption. The recipient's private key is used for decryption. One security property provided by signing that encryption does not include is authentication as a signature can't be recreated by anyone else but anyone with a public key can encrypt a message to you. 
5. The much smaller Ed25519 key is not necessarily the weaker key because RSA can be attacked with fairly efficient factoring methods, so it needs a huge key to stay secure. Elliptic curve keys have no shortcut attack like that, so a much smaller Ed25519 key gives about the same level of security.
